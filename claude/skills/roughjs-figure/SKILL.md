# rough.js で docs 用の図を作る

図は「描画コード (`<name>.js`) + 生成した PNG (`<name>.png`)」の組で `docs/figures/` に置く。
PNG は直接編集せず、`*.js` を直して再生成する。

## 構成

| ファイル | 役割 |
|---|---|
| `<name>.js` | 図 1 枚。1 行目が `// size: <幅>x<高さ>`、本体は `Fig.define({ w, h, draw })` |
| `<name>.png` | `render.sh` の出力 (2 倍解像度)。docs から相対パスで参照する |
| `_lib.js` | 箱・矢印・文字のヘルパーと固定パレット。`_` 始まりは図として扱わない |
| `render.sh` | headless Chrome で `*.js` を描画して PNG を撮る |

`templates/` に `_lib.js` / `render.sh` / 図の例 (`example-figure.js`) がある。
新しいリポジトリに導入するときは `docs/figures/` へそのままコピーする。

## 何を図にするか

図にするのは次の 2 種類だけにする。
手順を箱と矢印で並べただけのフローチャートは、本文の箇条書きで足りるので、相当複雑でない限り描かない。

- **契約 (interface) の依存関係**：CRD / API 同士の所有 (ownerReference)、名前による参照 (`xxxRef`)、どのコンポーネントがどの型を定義し、どの型を読むか。API group やパッケージの境界をまたぐ参照はどれか
- **実際のコンポーネント間のやり取り**：Pod、Deployment、DaemonSet、kube-apiserver、kubelet、外部 API (AWS など) を箱にして、誰が何を読み、何を書き、何を呼ぶか

描く前に、図の中心がこのどちらなのかを決める。
「A して B して C する」としか言えないなら、図にせず本文に書く。

### 描くときの観点

- **箱は実在するものにする**：Pod、コンポーネント、API オブジェクト、外部 API など、運用で指させるものを箱にする。「候補を絞る」「照合」のような処理の段階を箱にしない
- **中継点を省略しない**：controller 同士の連携は kube-apiserver 上のオブジェクトを介しているので、controller から controller へ直接矢印を引かない。kubelet → kube-apiserver → controller のように、実際の経路で描く
- **矢印の種類に意味を持たせる**：所有 / 名前で参照 / watch (読む) / 作る・削除する / API 呼び出しなどを線種と色で分け、図の上に凡例を置く
- **矢印の向きを揃える**：呼ぶ側 → 呼ばれる側、書く側 → 書かれるオブジェクト、参照する側 → 参照先。向きはソースで確認する
- **境界を描く**：API group、パッケージ (core / provider)、クラスタの内と外、AWS アカウントなど、契約の境界は囲みや線で示し、境界をまたぐ矢印が何かを読めるようにする
- **具体例で描く**：「インスタンス」より「g6.xlarge × AZ 1c」、「Pod」より「Pending Pod × 16 (gpu: 1)」のように、数や名前を入れて動作を連想できるようにする

### 番号 (①②③) の付け方

Kubernetes の controller は状態駆動で、決まった実行順序を持たない。
番号を振ると、イベント駆動の呼び出しの連鎖に見えるので、扱いを決めておく。

- 番号は、状態を書き換える操作 (オブジェクトを作る、書き換える、API を呼ぶ) にだけ振る
- 常に続いている watch には番号を振らない。ラベルは「watch」「watch (常時)」にする
- controller 同士に順序がない構成図には番号を振らず、「各 controller は kube-apiserver の状態だけを見て独立に reconcile する (順序なし)」のように図の中に明記する
- 同期 API 呼び出しの内側のように、順序が事実として決まっている場合は番号を振ってよい
- 番号を振った図には「番号は典型的な 1 回分の流れ」と注記する

## 手順

1. 描く前に、図の中心が「契約の依存関係」か「コンポーネント間のやり取り」かを決め、この図が見せる主張を 1 つに絞る。1 枚に詰めず、役割ごとに分ける
2. `<name>.js` を書く。座標は viewBox 上のピクセルで、幅は 900 を基準にする
3. `./render.sh <name>` で PNG を作り、**Read で画像を見て確認する**。コードだけ見て出さない
4. 重なり・欠けを直して再生成する。確認と修正は図ごとに最低 1 周する
5. markdown から `![説明](../figures/<name>.png)` で参照し、`*.js` と `*.png` を同じコミットに入れる

## render.sh の前提

- `google-chrome` が headless で動くこと。別名なら `CHROME=chromium ./render.sh`
- rough.js と Klee One (Google Fonts) を実行時に CDN から取る。ネットワークが要る
- 日本語は Noto Sans CJK JP が fallback。Klee One が取れないと字形が変わる

rough.js は `https://cdn.jsdelivr.net/npm/roughjs@4.6.6/bundled/rough.js` を使う。
cdnjs の `rough.js/4.6.6/rough.min.js` は 404 なので使わない。

## ヘルパー (`d`)

| ヘルパー | 用途 |
|---|---|
| `d.box(x, y, w, h, title, sub, color, {size})` | 色付きの箱。`sub` は 1 行の補足 |
| `d.group(x, y, w, h, label, color, dashed)` | 囲み枠 |
| `d.arrow(x1, y1, x2, y2, label, {color, dashed, dx, dy})` | 矢印。ラベルは中点に置かれ、`dx` / `dy` でずらす |
| `d.poly(points, {color, dashed})` | 折れ線の矢印。ラベルは付かないので `d.text` を別に置く |
| `d.line(x1, y1, x2, y2, color, width)` | 矢じりなしの線。バツ印や括り線に使う |
| `d.text(x, y, s, {anchor, size, bold, color})` | `anchor` は `middle` (既定) / `start` / `end` |
| `d.lines(x, y, [..], {lh})` | 複数行の文字 |
| `d.legend()` | 依存図の凡例 (作る / 名前で参照 / label で選ぶ) |

色は `plat` (青) / `svc` (橙) / `pod` (紫) / `ok` (緑) / `warn` (赤)。意味は図ごとに固定する。
PNG は白背景・固定パレットで出すので、mkdocs の light / dark のどちらでも読める。

## 描くときの規則

- **矢印にはラベルを付ける。** 無印の矢印は「関係がある」以上を伝えない
- **比較なら差分を描く。** 選択肢ごとの箱を並べるだけでは比較にならない
- **事実は確認してから描く。** 参照関係・既定値・挙動は、マニフェストや OSS のソースで裏を取る。推測を矢印にしない
- **図に書く文字は短くする。** 説明文は図の下の本文に書く

## レイアウトで繰り返し起きた失敗

画像を見て初めて分かったもの。描いたら必ず確認する。

| 症状 | 原因と直し方 |
|---|---|
| 右端・下端が切れる | rough.js の線が箱の外にはみ出す。端から 10〜15px 空ける。最後の箱は幅 900 の手前で終える |
| ラベルが矢印や箱に重なる | 斜めの矢印の中点にラベルが乗る。`dx` / `dy` で逃がすか、`d.text` を空き地に置く |
| 別の矢印が文字を貫通する | 迂回させる。`d.poly` で直角に曲げ、文字は折れ線の内側に置く |
| 矢印が交差して主張が読めない | 配置が悪い。行の並び順を変えて交差を無くす。直らないなら図を分ける |
| 日本語ラベルが箱からはみ出す | Klee One は幅広い。1 行 10 文字前後を目安に `d.lines` で折る |
| 下に余白が余る | `// size:` の高さを内容に合わせて詰める。`h` も同じ値にする |
| 囲み (group) のあいだのラベルが枠線に重なる | 囲みの隙間が 60px 前後だとラベルが入らない。隙間を 90px 以上空けるか、ラベルを囲みの内側・上下の空き地に置く。凡例で意味が通るならラベル自体を消す |
| 矢印の始点や終点が箱から外れる | 箱の座標を動かしたのに矢印の x / y を追従させていない。箱を動かしたら、その箱に出入りする矢印の座標も見直す |

## 再生成を前提にする

- 乱数 seed は `_lib.js` が描画順に振るので、描く順番を変えると線の揺れ方が変わる。差分を最小にしたいときは順番を保つ
- 図を直したら該当図だけ `./render.sh <name>`。共通ヘルパー (`_lib.js`) を直したら全図を再生成する
- 図の一覧と再生成手順は `docs/figures/README.md` に書き、docs 本文から 1 行でリンクする
